## Database

Room version 2, migration 1→2 adds notes.viewMode. Tables: notebooks, notes, tags, note_tags, comments, bookmarks, footnotes, versions, templates, reminders. Long auto IDs for entities, UUID document blocks. Notes indexed by notebookId, updatedAt, trashed; tags uniquely indexed by name. No declared foreign keys. Schema export disabled. Destructive fallback enabled (data-loss risk on missing migration). No FTS: leading-wildcard LIKE over JSON is a scan, not indexed content search. No committed schema snapshots.

## Confirmed defects / risks

- Repository `@Transaction` on mergeNotebook has no effect: only DAO/Room-generated transaction methods enforce it. Snapshot insert/prune and version restore are also multi-step without a transaction.
- Deserialization silently skips corrupt blocks and maps unknown block types to paragraphs. Re-saving can permanently discard content; malformed JSON becomes a blank editable document.
- Editor back action launches a composition-scoped save then navigates immediately, allowing cancellation before persistence. No system-back save handler or background save observer found. Concurrent save completion clears dirty regardless of newer edits.
- Model downloads accept content without trusted checksum/magic verification, count `.part` files as installed, remove partial downloads, and have no inference runtime.
- Online AI constructs JSON manually (control-character/model escaping defects), follows default redirects, and lacks an explicit HTTPS validation contract.
- lint/release assembly use continue-on-error; CI green does not establish these stages passed.
- PIN uses PBKDF2 (legacy SHA-256 migration exists), not the outdated README claim. Keystore API key encryption exists; backup policy needs review because restored preferences may reference non-restored Keystore keys.
- Full visual export fidelity is not demonstrated by ZIP/XML validity/PDF magic. Drawing is rasterized; tables only have plain string cells; no model for sections, editable stroke geometry or cell rich text.
- No physical-device, stress, full backup, or native inference evidence. Large JSON/editor recomputation and image-heavy documents need profiling.
